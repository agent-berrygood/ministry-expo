# 사역박람회 웹앱 PRD

> 이 문서는 개발의 **단일 기준(Source of Truth)**이다. 구현과 이 문서가 다르면 문서를 먼저 고치고 코드를 맞춘다.
> 상태: 초안 v0.7 · 작성일 2026-10-15

---

## 1. 개요

### 1.1 한 줄 정의
교회의 모든 사역 부서를 **가상 박람회장의 부스**로 배치하고, 지도앱 거리뷰처럼 **클릭으로 이동하며 둘러보는** 웹앱.

### 1.2 배경
- 성도들이 어떤 사역 부서가 있는지, 각 부서가 무엇을 하는지, 어떻게 참여하는지 한눈에 알기 어렵다.
- 오프라인 박람회(예: 코엑스 SOVAC 사회적 가치 페스타)처럼 부스를 돌아다니는 경험을 웹으로 제공해 **탐색의 재미**와 **참여 신청**을 연결한다.

### 1.3 목표
| # | 목표 | 측정 기준 |
|---|---|---|
| G1 | 모든 사역 부서를 한 공간에서 소개 | 33개 부스 전부 노출 |
| G2 | 휴대폰에서 설치 없이 바로 체험 | QR → 첫 화면까지 5초 이내(4G 기준) |
| G3 | 관심 부서로 참여 연결 | 부스마다 "참여하기" 링크 동작 |
| G4 | 비개발자도 내용 수정 가능 | 부서 내용은 `data/*.json`만 고치면 반영 |

### 1.4 하지 않는 것 (Non-goals)
- 봉사자 명단·연락처 게시 — **포함하지 않는다.** 예외: 본인 동의를 받은 부스 담당자와 목회자의 사진, 그리고 사진 파일명으로 정한 이름 (4.8).
- 로그인, 회원 관리, 서버 DB
- 자유 이동(WASD/1인칭 걷기). 이동은 정해진 지점 사이로만 한다.
- 게임 수준의 실시간 실사 그래픽. 휴대폰에서 돌아가는 범위 안에서 실사에 가깝게 한다(7.1).

| 사용자 | 상황 | 필요 |
|---|---|---|
| 일반 성도 | 주보·현장 QR로 휴대폰 접속 | 쉽게 둘러보고 관심 부서에 신청 |

## 3. 박람회 구성 (정보 구조)

### 3.1 존과 부스
부스 ID는 영문 kebab-case로 정하고 **한 번 정하면 바꾸지 않는다**(URL·데이터 키로 쓰임).

| 존 ID | 존 이름 | 색상 토큰 | 부스 (ID — 이름) |
|---|---|---|---|
| `worship` | 예배사역 | `--zone-worship` | `galilee` 갈릴리예배부 · `bethesda` 베데스다예배부 · `worship-support` 예배지원부 · `zion-choir` 시온찬양대 · `gloria-choir` 글로리아찬양대 · `breathing-band` 브리딩밴드 |
| `mission` | 선교사역 | `--zone-mission` | `overseas-1` 해외선교1부 · `overseas-2` 해외선교2부 · `youth-mission` 청소년선교부 |
| `edu1` | 교육1부사역 | `--zone-edu1` | `preschool` 통합미취학부(2–7세) · `infant` 영유아부(2–4세) · `kindergarten` 유치부(5–7세) · `children` 통합아동부(초1–6) · `primary` 유년부(초1–3) · `junior` 소년부(초4–6) · `middle` 중등부(중1–3) · `high` 고등부(고1–3) |
| `edu2` | 교육2부사역 | `--zone-edu2` | `wonderful-senior` 원더풀시니어부 · `adult-edu` 장년교육부 · `culture-pr` 문화홍보부 |
| `youth` | 청년사역 | `--zone-youth` | `young-adult-1` 청년1부 · `young-adult-2` 청년2부 · `eoullim` 어울림 |
| `care` | 돌봄사역 | `--zone-care` | `newcomer` 새가족부 · `funeral` 상례부 · `warm-meal` 따뜻한한끼봉사부 |
| `sharing` | 나눔사역 | `--zone-sharing` | `joy-sharing` 기쁨나눔부 · `hope-sharing` 희망나눔부 · `love-sharing` 사랑나눔부 |
| `support` | 사역지원 | `--zone-support` | `finance` 재정부 · `intercession` 중보기도부 · `facilities` 관리부 · `transport` 차량봉사부 |

합계: 8개 존, 33개 부스.

**하위 부서 관계 (`parent`):** `infant`, `kindergarten` → `preschool` / `primary`, `junior` → `children`.
교육1부 존에서는 상위 부스를 중심으로 하위 부스를 묶은 "섬" 형태로 배치한다.

**나눔마당 (특별 구역):** `joy-sharing` 기쁨나눔부와 `warm-meal` 따뜻한한끼봉사부는 나눔사역 존과 돌봄사역 존의 경계에 **나란히** 붙여 배치한다.
- 소속 존(색상, 목록 보기 분류)은 그대로 둔다. 위치만 붙어 있고, 두 부스가 함께 쓰는 마당을 하나 둔다.
- 두 부스 모두 **장터형(`stall`) 넓은 부스**로 만든다 (4.2 참고).

### 3.2 선택 확장: 교구 광장 (Phase 4)
- 존 ID `parish`. 1–6교구와 청년교구를 안내판 형태로 표시하고, 지역(목장 이름)으로 "우리 동네 목장 찾기"를 제공한다.
- 목장지기·교구장 등 **이름은 표시하지 않는다.** 교구 번호, 지역명, 목장 수만 쓴다.

### 3.3 공간 배치

```
            [A worship] ── [B mission]
                 │              │
[H support] ── [중앙 광장 plaza] ── [C edu1]
                 │              │
[G sharing] ─ [나눔마당] ─ [F care] ── [D edu2] ── [E youth]
               joy-sharing │ warm-meal
                           │
                     [입구 entrance]
```

- 좌표계: Three.js 기본(Y 위쪽), **1 unit = 1 m**. 바닥은 y = 0 평면.
- 입구 `entrance`는 원점(0, 0, 0)에 두고, 박람회장은 −z 방향으로 펼친다.
- 부스 하나의 기본 크기: 가로 4 m × 깊이 3 m × 높이 3 m. 통로 폭은 최소 4 m.
- 넓은 부스(`size: "wide"`): 가로 8 m × 깊이 5 m. 나눔마당은 두 부스 앞에 8 m × 6 m 정도의 공용 마당을 둔다.
- 나눔마당은 입구에서 2~3번만 이동하면 닿는 위치에 두어, 박람회의 "따뜻한 첫인상"이 되게 한다.

## 4. 핵심 기능

### 4.1 거리뷰식 이동 (Navigation)
- 박람회장은 **노드 그래프**다. 노드는 사람이 서서 보는 지점(통로 교차점, 부스 앞)이다.
- 각 노드는 `position`(눈높이 y = 1.6), 기본 바라보는 방향 `yaw`, 연결된 이웃 노드 목록 `links`를 가진다.
- 바닥에 이웃 노드 방향으로 **화살표 핫스팟**을 표시한다. 클릭하거나 탭하면 카메라가 이동한다.
  - 이동 애니메이션: 0.8초, ease-in-out. 이동 중에는 입력을 무시한다.
- **둘러보기:** 드래그(마우스·터치)로 yaw는 360°, pitch는 −30°에서 +20°까지 회전한다. 위치는 바뀌지 않는다.
- 바닥 클릭 이동(선택): 클릭 지점에서 가장 가까운 연결 노드로 이동한다.
- 키보드: ←/→로 회전, ↑로 정면에 가장 가까운 화살표 방향으로 이동(↓는 뒤쪽), Esc로 패널을 닫는다.
- 시선 높이: 통로에서는 바닥 화살표가 보이도록 8° 내려다보고, 부스 앞 지점에 도착하면 수평으로 부스를 정면으로 본다.
- 화살표 규칙 (`src/nav/controller.ts`의 `targets()`):
  - 화살표 밑에는 어두운 반투명 원판을 깔아 밝은 바닥에서도 보이게 한다. 원판이 클릭 영역이다.
  - 부스 앞에 서 있을 때 1.5 m 안의 통로 지점은 화살표를 만들지 않고, 그 통로 지점의 이웃을 직접 가리킨다.
  - 3 m 안의 부스 시점(맞은편 부스)으로 가는 화살표는 시점 위치가 아니라 부스 건물 쪽을 가리킨다.
  - 방향 차이가 25° 안인 화살표는 하나로 합치고, 부스 쪽 이웃을 우선한다.

### 4.2 부스 (Booth)
- 부스는 `data/booths.json`의 데이터로 **자동 생성**한다. 수작업 배치 좌표는 `data/layout.json`에만 둔다.
- 부스 템플릿(`template`)은 두 가지다. 새 템플릿을 추가하려면 이 표를 먼저 갱신한다.

| 템플릿 | 형태 | 사용 부스 |
|---|---|---|
| `standard` | 바닥 + 뒷벽 + 간판(부서명) + 존 색상 띠 + 선택 소품(`prop`) | 나머지 전부 |
| `stall` | 장터·포장마차형. 아래 참고 | `joy-sharing`, `warm-meal` |

- `standard` 부스끼리의 차이는 간판 텍스트, 색, 소품뿐이다.

**`stall` 장터형 부스 구성:**
- 줄무늬 천막 지붕(존 색상 + 흰색)과 나무 기둥, 손글씨 느낌의 나무 간판
- 앞쪽 조리대에 **전 부치는 철판**과 전 접시, 김이 모락모락 오르는 연출(간단한 파티클 또는 반투명 스프라이트)
- 앞마당에 낮은 테이블과 의자 2~3세트, 기둥 사이에 전구줄(따뜻한 노란 조명)
- 부스 성격에 맞는 소품
  - `warm-meal` 따뜻한한끼봉사부: 큰 국솥, 밥공기, 쟁반
  - `joy-sharing` 기쁨나눔부: 나눔 상자, 선물 꾸러미, 손글씨 메모판
- 조명은 장터 쪽만 색온도를 낮춰(따뜻한 주황빛) 박람회장 안에서 눈에 띄게 한다.
- (선택) 지글지글 소리: 기본은 꺼 두고, 사용자가 소리 켜기를 눌렀을 때만 나눔마당 근처에서 작게 재생한다.
- 모델은 처음에 코드로 만든 단순 형태로 시작하고, P3에서 Blender 모델(`stall.glb` + 소품 `.glb`)로 바꾼다.
- 부스를 클릭하면 ① 해당 부스 앞 노드로 이동하고 ② 정보 패널을 연다.
- 호버(데스크톱)나 시선 중앙(모바일)에 있는 부스는 외곽선으로 강조한다.

### 4.3 정보 패널 (Booth Panel)
DOM 오버레이로 구현한다. 모바일에서는 아래에서 올라오는 시트, 데스크톱에서는 오른쪽 사이드 패널로 연다.

| 항목 | 필드 | 필수 |
|---|---|---|
| 부서명 + 존 배지 | `name`, `zone` | ✅ |
| 한 줄 소개 | `tagline` | ✅ |
| 하는 일 | `description` (3–5문장) | ✅ |
| 대상 | `audience` (예: "초1–3학년") | – |
| 모임 시간·장소 | `schedule` | – |
| 활동 사진 | 폴더에서 자동 수집 (4.6 참고) | – |
| 영상 | `video` (YouTube URL) | – |
| 참여하기 버튼 | `joinUrl` | – (없으면 버튼 숨김) |
| 하위 부서 | `parent`로 자동 계산 | – |

### 4.4 길찾기 보조
- **미니맵:** 화면 구석에 평면도를 표시하고 현재 위치와 바라보는 방향을 보여 준다. 부스 근처(5 m 안)를 탭하면 그 부스로, 그 밖을 탭하면 가장 가까운 통로 지점으로 이동한다.
- **검색:** 부서명이나 존 이름으로 검색한다. 결과를 선택하면 그 부스로 이동한 뒤 패널을 연다.
- **목록 보기:** 3D 없이 존별 부스 목록을 보여 준다. 어르신·저사양 기기용이며 접근성 요구사항이다.

### 4.5 딥링크
- URL 해시로 상태를 표현한다: `#/booth/{boothId}`, `#/zone/{zoneId}`, `#/list`
- 링크로 들어오면 해당 위치에서 바로 시작한다. 부서별 QR을 만들 수 있게 하기 위해서다.

### 4.6 사진 자동 반영
**원칙: 사진은 폴더에 넣으면 생기고, 빼면 사라진다. JSON을 고칠 필요가 없다.**

**폴더 규칙**
- 위치: 저장소 루트의 `photos/` 아래 부스별 폴더
- 폴더 이름: `{boothId}_{부서명}` (예: `photos/zion-choir_시온찬양대/`)
  - 매칭은 `_` 앞의 `boothId`로만 한다. `_` 뒤의 한글 이름은 사람이 알아보기 위한 것이라 틀려도 동작한다.
  - `npm run photos:init`을 실행하면 33개 부스 폴더를 한 번에 만든다(이미 있으면 건너뜀).
- 지원 형식: `.jpg` `.jpeg` `.png` `.webp`. 그 밖의 형식(HEIC 등)은 건너뛰고 경고를 출력한다.

**파일 이름 규칙**
| 규칙 | 예 | 결과 |
|---|---|---|
| 순서 | `01-`, `02-` 접두어 | 숫자 순서대로 표시. 접두어가 없으면 파일명 가나다순 |
| 설명 | 접두어 뒤 파일명 | 사진 설명으로 사용. `01-여름수련회.jpg` → "여름수련회" |
| 대표 사진 | `cover.jpg` 또는 첫 번째 사진 | 패널 맨 앞에 보이고, 3D 부스 벽 액자에 걸림 |
| 숨기기 | 파일명이 `_`로 시작 | 반영하지 않음 (지우지 않고 잠시 빼고 싶을 때) |

- 부스당 최대 12장을 반영한다. 넘으면 앞에서부터 12장만 쓰고 경고를 출력한다.

**처리 과정** (`scripts/build-photos.ts`, sharp 사용)
1. `photos/`의 부스 폴더를 읽는다.
2. 원본이 크면(긴 변 1600px 초과 또는 1 MB 초과) **그 자리에서 줄인다.** 이렇게 해서 저장소에 큰 파일이 쌓이지 않게 한다.
   - 줄이기 전에 원본을 **구글 드라이브 원본 보관소**에 먼저 복사한다(아래 "원본 보관소" 참고).
   - 복사한 파일의 크기가 원본과 같은지 확인한 **뒤에만** 줄인다. 보관소에 접근할 수 없거나 복사에 실패하면 그 파일은 줄이지 않고 경고만 출력한다. **원본을 백업 없이 덮어쓰는 일은 없어야 한다.**
3. 웹용 이미지를 만든다 → `public/photos/{boothId}/`
   - 패널용: WebP, 긴 변 1280px
   - 부스 액자·목록 썸네일용: WebP, 긴 변 512px
   - 출력 파일명은 `{순번}-{해시}.webp` 같은 영문으로 만든다(한글 URL 문제 방지).
4. **메타데이터(EXIF, GPS 위치)를 모두 지운다.** 개인정보 보호를 위해 필수다.
5. 목록 파일 `public/data/photos.json`을 만든다(5.5 참고).

**언제 실행되나**
| 상황 | 동작 |
|---|---|
| 개발 서버(`npm run dev`) | Vite 플러그인이 `photos/`를 감시한다. 파일을 넣거나 빼면 자동으로 다시 처리하고 화면을 새로 고친다 |
| 빌드(`npm run build`) | 빌드 전에 항상 실행된다 |
| 배포 | `photos/`를 커밋하고 push하면 배포 빌드에서 처리된다 |

- `public/photos/`와 `photos.json`은 **생성물**이라 깃에 넣지 않고 손으로 고치지 않는다.
- 알 수 없는 부스 ID의 폴더가 있으면 경고를 출력한다(`validate`).
- `photos/`에 1 MB가 넘는 파일이 남아 있으면(백업 실패 등) `validate`가 경고한다.

**원본 보관소 (구글 드라이브)**
- 위치: 구글 드라이브 `내 드라이브/사역박람회/assets-src/photos/{boothId}_{부서명}/`
- 경로는 컴퓨터마다 드라이브 문자가 다를 수 있으므로 코드에 적지 않고 **`.env.local`의 `PHOTO_ORIGINALS_DIR`**로 지정한다.
  - `.env.local`은 깃에 올라가지 않는다. 새 컴퓨터에서는 `.env.example`을 복사해 경로만 맞춘다.
  - 데스크톱(현재): `J:\내 드라이브\사역박람회\assets-src\photos`
- 같은 이름의 파일이 이미 보관소에 있으면 덮어쓰지 않고 `파일명 (2).jpg`처럼 번호를 붙여 저장한다.
- 스크립트는 Node 내장 `--env-file` 옵션으로 `.env.local`을 읽는다(추가 의존성 없음).
- 보관소에서 웹앱 쪽으로 무언가를 지우거나 동기화하지 않는다. **보관소는 쓰기(추가)만 한다.**

### 4.7 스탬프 투어 (선택, Phase 4)
- 부스 패널을 열면 그 부스를 방문 처리한다. 진행 상황은 `localStorage`에 저장한다(실패해도 앱은 정상 동작).
- 존별 진행률을 표시하고, 모두 방문하면 완료 화면을 보여 준다.

### 4.8 사진 인물 (공통)
- 사진 한 장을 세운 판(세로축 빌보드)으로 사람을 세운다. 판은 항상 방문자 쪽으로 돈다. 부스는 정면·비스듬한 앞에서만 보므로 평면인 티가 거의 나지 않는다.
- 사진은 **배경을 지운 투명 PNG**를 권장한다. 배경이 남아 있으면 경고만 하고 그대로 쓴다.
- 사진이 없는 자리에는 실루엣을 세운다(목회자는 정장 실루엣, 담당자는 존 색 조끼와 이름표).
- 처리: `scripts/build-figures.ts`(sharp)가 회전 보정 → 투명 가장자리 잘라내기 → 높이 768px → WebP로 바꾸고 메타데이터(GPS 등)를 지운다. 결과는 `public/figures/`와 `public/data/figures.json`(생성물, 깃 제외).
- 실행 시점: 개발 서버는 `photos/`를 감시해 바뀌면 다시 처리하고 새로 고친다. 빌드할 때도 항상 실행된다(Vite 플러그인).
- 파일명의 숫자 접두어 뒤는 이름(캡션)이 된다. 예: `01-강세원 목사.png` → "강세원 목사". `_`로 시작하는 파일은 반영하지 않는다.
- 폴더: `npm run photos:init`이 부스 폴더 33개와 `_entrance`, `_hidden`을 만든다. 규칙 안내는 `photos/README.md`.

| 인물 | 넣는 곳 | 사진 | 세우는 곳 |
|---|---|---|---|
| 부스 담당자(부장) | `photos/{boothId}_{부서명}/staff.png` | 머리 위~허리, 정면 | 데스크 뒤 오른쪽. 사진 아래 끝(0.82 m)은 데스크 상판(1.11 m)에 가려진다 |
| 입구 환영(담임목사) | `photos/_entrance/`의 첫 사진 | 전신, 정장 | 입구 게이트 앞 왼쪽 + "환영합니다!" 말풍선 |
| 숨은 목회자 | `photos/_hidden/`의 사진들 | 전신, 정장 | `layout.json`의 숨는 자리에 파일명 순서대로 |

- 담당자 판을 누르면 그 부스를 누른 것과 같다. 일반 부스 포스터는 담당자 자리를 비우려고 왼쪽 위로 옮겼다.

### 4.9 입구 환영
- 첫 화면(입구)에서 담임목사님이 게이트 앞에서 맞이한다. 위치는 `layout.figures.entrance`.

### 4.10 숨은 목회자 찾기
- 정장 차림의 목사님·전도사님이 박람회장 곳곳(기둥 뒤, 나무 화단 뒤, 장터 주방, 부스 사이, 통로 끝)에 숨어 있다.
- 누르면 살짝 뛰어오르고 "○○ 목사님을 찾았어요! (3/8)" 알림이 뜬다. 왼쪽 위 칩에 진행 상황을 보여 주고, 모두 찾으면 축하 문구로 바뀐다.
- 찾은 기록은 `localStorage`(`expo.hunt.v1`)에만 남는다. 저장이 막혀도 이번 방문 동안은 동작한다.
- 숨는 자리는 `layout.json`의 `figures.hidden`에서 관리한다. `validate`가 ID 중복과 이동 지점과의 거리(1 m 이상)를 검사한다.
- 사진이 있으면 사진 수만큼(자리 수까지), 없으면 모든 자리에 실루엣을 세운다.

## 5. 데이터 스키마

모든 콘텐츠는 `public/data/`의 JSON에서 읽는다. **코드 안에 부서 이름이나 문구를 하드코딩하지 않는다.**

### 5.1 `zones.json`
```json
[
  {
    "id": "worship",
    "name": "예배사역",
    "color": "#7C5CFF",
    "order": 1,
    "entryNode": "n-worship-gate"
  }
]
```

### 5.2 `booths.json`
```json
[
  {
    "id": "zion-choir",
    "zone": "worship",
    "name": "시온찬양대",
    "parent": null,
    "tagline": "",
    "description": "",
    "audience": "",
    "schedule": "",
    "video": "",
    "joinUrl": "",
    "template": "standard",
    "size": "standard",
    "prop": "music"
  }
]
```
- `template` 허용값: `standard` | `stall` (기본값 `standard`)
- `size` 허용값: `standard` | `wide` (기본값 `standard`)
- `prop` 허용값: `none` | `music` | `globe` | `book` | `heart` | `cross` | `meal` | `car` | `pray` | `gift`
  - `stall` 템플릿은 템플릿 안에 소품이 정해져 있으므로 `prop`을 무시한다.
- 나눔마당 두 부스의 값: `{"template": "stall", "size": "wide"}`. `warm-meal`의 `prop`은 `meal`, `joy-sharing`은 `gift`로 둔다(목록 보기 아이콘에 사용).
- 빈 문자열은 "아직 내용 없음"을 뜻한다. 패널은 빈 필드를 숨긴다.

### 5.3 `layout.json`
```json
{
  "booths": { "zion-choir": { "x": -12, "z": -20, "rotY": 90 } },
  "nodes": [
    { "id": "entrance", "x": 0, "z": 0, "yaw": 180, "links": ["n-plaza-s"] },
    { "id": "n-booth-zion-choir", "x": -9, "z": -20, "yaw": 270, "links": ["n-worship-gate"], "booth": "zion-choir" }
  ]
}
```
- 노드 ID 규칙: `n-{zone|plaza}-{설명}`, 부스 앞 노드는 `n-booth-{boothId}`
- `links`는 **양방향으로 적는다**. 빌드 시 검증 스크립트가 짝이 맞는지 확인한다.

### 5.4 데이터 검증
`npm run validate` 스크립트로 다음을 검사하고, 하나라도 실패하면 빌드를 막는다.
- ID 중복 없음, 모든 `zone`/`parent`/`booth`/`links` 참조가 실제로 존재함
- 모든 부스에 `layout.booths` 좌표와 `n-booth-{id}` 노드가 있음
- 노드 그래프가 `entrance`에서 모두 도달 가능함
- `joy-sharing`과 `warm-meal`의 부스 앞 노드가 서로 직접 연결(`links`)되어 있음 (나눔마당 인접 규칙)
- 개인정보 의심 패턴(전화번호 형식, "집사/권사/장로/목사" 직분 + 이름 형태) 경고
### 5.5 `photos.json` (자동 생성, 수정 금지)
```json
{
  "zion-choir": [
    {
      "src": "photos/zion-choir/01-a1b2c3.webp",
      "thumb": "photos/zion-choir/01-a1b2c3.thumb.webp",
      "caption": "여름수련회",
      "width": 1280,
      "height": 853,
      "cover": true
    }
  ]
}
```
- 사진이 없는 부스는 키가 없다. 이때 패널은 사진 영역을 숨기고, 부스 액자에는 존 색상의 기본 그림을 건다.

### 5.6 인물 데이터
- `layout.json`의 `figures`: `entrance: {x, z}`, `hidden: [{id, x, z}]` (손으로 관리)
- `figures.json` (생성물): `{ staff: {boothId: FigureImage}, entrance: FigureImage | null, hidden: FigureImage[] }`, `FigureImage = {src, aspect, caption}`

## 6. 기술 스택과 구조

### 6.1 스택 (고정)
| 영역 | 선택 | 비고 |
|---|---|---|
| 언어 | TypeScript (strict) | |
| 번들러 | Vite | |
| 3D | Three.js | 다른 3D 엔진, React Three Fiber 사용 안 함 |
| UI | 순수 DOM + CSS | UI 프레임워크 사용 안 함 (가볍게 유지) |
| 애니메이션 | 자체 tween 유틸 | 외부 라이브러리 최소화 |
| 스크립트 실행 | tsx (개발 의존성) | `scripts/*.ts`를 바로 실행 (`npm run validate`) |
| 3D 에셋 | glTF Binary (`.glb`) | Blender에서 내보냄 |
| 이미지 처리 | sharp (개발 의존성) | 사진 축소·WebP 변환·메타데이터 제거 (4.6) |
| 호스팅 | GitHub Pages 또는 Netlify (정적) | 서버 없음 |
| 패키지 관리 | npm | `package-lock.json` 커밋 |

의존성을 추가하려면 이 표를 먼저 갱신한다.

### 6.2 폴더 구조
```
/
├─ docs/
│  └─ PRD.md                ← 이 문서
├─ photos/                  ← ★ 사진 넣는 곳 (4.6). 부스별 폴더 {boothId}_{부서명}/
├─ .env.example             ← 컴퓨터별 설정 예시 (PHOTO_ORIGINALS_DIR)
├─ .env.local               ← 이 컴퓨터의 실제 설정 (깃 제외)
├─ public/
│  ├─ data/                 ← zones.json, booths.json, layout.json (+ photos.json 생성물)
│  ├─ models/               ← .glb (웹용 최적화본만)
│  └─ photos/{boothId}/     ← 생성물: 웹용 WebP (깃 제외, 손대지 않음)
├─ src/
│  ├─ main.ts               ← 진입점: 데이터 로드 → 씬 → UI 연결
│  ├─ data/                 ← 타입 정의(types.ts), 로더, 검증
│  ├─ scene/                ← 씬, 조명, 바닥, 부스 생성(boothFactory.ts)
│  ├─ nav/                  ← 노드 그래프, 카메라 이동, 화살표 핫스팟, 둘러보기
│  ├─ ui/                   ← 패널, 미니맵, 검색, 목록 보기
│  ├─ router.ts             ← 해시 라우팅
│  └─ styles/               ← tokens.css, 컴포넌트 CSS
├─ scripts/
│  ├─ validate-data.ts
│  ├─ build-photos.ts       ← 활동 사진 처리 + photos.json 생성 (예정)
│  ├─ build-figures.ts      ← 인물 사진 처리 + figures.json 생성
│  └─ init-photo-folders.ts ← 부스별·인물 사진 폴더 생성
└─ index.html
```

### 6.3 모듈 경계
- `scene/`은 DOM을 직접 건드리지 않는다. `ui/`는 Three.js 객체를 직접 건드리지 않는다.
- 둘 사이의 통신은 이벤트 버스(`src/events.ts`)를 통한다.
  - 이벤트: `booth:select`, `booth:hover`, `nav:arrive`, `nav:goto`, `nav:pose`(미니맵용 카메라 위치·방향), `panel:close`, `route:change`
- `main.ts`가 조립을 맡는다. 데스크톱 사이드 패널이 열리면 `World.setRightInset()`으로 3D 화면 중심을 패널 왼쪽으로 옮긴다.
- 상태(현재 노드, 열린 부스)의 원본은 `router` + `nav` 하나뿐이다.

## 7. 디자인 원칙

### 7.1 시각 스타일
- 일러스트풍 로우폴리. 밝은 바닥, 부드러운 그림자, 채도 높은 존 색상 포인트.
- 조명: 환경광 + 방향광 1개. 그림자는 방향광 하나만, 모바일에서는 끈다.
- 간판 텍스트는 Canvas 텍스처로 그린다. 폰트는 Pretendard.
- **실사 방향 (v0.7)**:
  - 질감 아틀라스(칠한 벽·나무결·천·돌) 한 장을 코드로 생성해 도형마다 고른다(`MeshBuilder.use()`). 질감이 달라도 드로우콜이 늘지 않는다.
  - 옅은 하늘색 하늘, 살짝 광택 있는 2 m 콘크리트 타일 바닥, 금속 트러스.
  - 데스크톱 전용 후처리: 주변광 차폐(GTAO) + 전구만 번지는 블룸. 휴대폰은 끈다.
  - 거리 인원은 줄였다(`DECOR.visitorNone`, `walkerGap`).
- 분위기 연출 (`src/scene/decor.ts`, 수치는 `config.ts`의 `LIGHT`·`DECOR`):
  - 그라데이션 하늘, 환경 반사(RoomEnvironment), 따뜻한 햇빛, CSS 비네트
  - 타일 바닥, 테두리 있는 통로 카펫, 통로 위 트러스·펜던트 조명·삼각 깃발
  - 사람 실루엣(고정 시드로 매번 같은 배치, 이동 지점·화살표 자리는 비움), 광장 나무 화단과 벤치, 입구 풍선
  - 실시간 그림자가 꺼지는 휴대폰을 위해 부스·사람·나무 밑에 부드러운 그림자 판을 깐다
- 일반 부스 시점은 통로 중심에서 1.4 m 떨어진 맞은편에 둔다(휴대폰 세로 화면에서 부스 전체가 보이도록).

### 7.2 디자인 토큰
색·간격·글자 크기는 `src/styles/tokens.css`의 CSS 변수로만 쓴다. 3D 색상도 `zones.json`의 `color`에서 가져온다.
- 다크 모드: UI 오버레이만 대응한다. 3D 씬은 단일 테마로 한다.
- 본문 최소 16px. 터치 영역 최소 44×44px.

### 7.3 문구 톤
- 존댓말, 짧고 따뜻하게. 예: "함께하고 싶어요" (참여 버튼), "여기서 시작해요" (입구)

## 8. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 초기 로딩 | 전송량 3 MB 이하(사진 제외), 4G에서 5초 안에 첫 화면 표시 |
| 프레임 | 중급 안드로이드 기기 30fps 이상, 데스크톱 60fps |

| 파티클 | 김 연출은 부스당 파티클 50개 이하. 화면 밖이거나 멀리 있으면 정지 |
| 소리 | 자동 재생 금지. 사용자가 켰을 때만 재생 |
| 사진 | WebP, 긴 변 1280px, 1장 300 KB 이하, 지연 로딩. 패널을 열 때 해당 부스 사진만 불러옴. 부스 액자는 512px 썸네일을 가까운 부스만 로드 |
| 브라우저 | 최신 Chrome, Safari(iOS 16+), Samsung Internet, Edge |
| 접근성 | 목록 보기 제공, 패널 키보드 조작 가능, 색 대비 4.5:1 이상 |
| WebGL 미지원 | 자동으로 목록 보기로 전환 |
| 개인정보 | 명단·연락처 미포함. 인물 사진은 본인 동의를 받은 담당자·목회자만. 메타데이터는 자동 삭제 |
| 인물 사진 | 높이 768px WebP, 1장 150 KB 안팎 |

## 9. 개발 규칙

### 9.1 코드
- TypeScript strict, `any` 금지(불가피하면 주석으로 이유를 남김).
- 파일명은 camelCase(`boothFactory.ts`), 클래스는 PascalCase, 상수는 UPPER_SNAKE.
- 매직 넘버(크기, 시간, 각도)는 `src/config.ts`에 모은다.
- 사용하지 않게 된 Three.js 리소스는 `dispose()`한다.

### 9.2 깃
- 브랜치: `main`은 항상 배포 가능 상태로 유지하고, 작업은 `feat/…`, `fix/…`, `content/…` 브랜치에서 한다.
- 커밋 메시지: `type: 요약` 형식 (`feat`, `fix`, `content`, `style`, `refactor`, `docs`, `chore`)
  - 예: `feat: 화살표 핫스팟 클릭 이동`, `content: 시온찬양대 소개 추가`
- 여러 컴퓨터에서 작업할 때: **시작 전 `git pull`, 끝나면 `git push`.**
- Blender 원본(`.blend`)과 고화질 원본 사진은 깃에 넣지 않고 구글 드라이브에 둔다.

### 9.3 에셋 파이프라인
구글 드라이브 원본 보관소 구조:
```
내 드라이브/사역박람회/assets-src/
├─ README.txt
├─ photos/      ← 사진 원본 (스크립트가 자동 백업)
└─ blender/     ← Blender 원본 .blend
```
1. Blender 원본은 `assets-src/blender/`에 둔다.
2. 내보내기: glTF Binary, +Y Up, 적용된 모디파이어, 압축 사용
3. 결과물만 `public/models/`에 넣고 커밋한다.
4. 사진은 `photos/{boothId}_{부서명}/`에 넣기만 하면 된다(4.6). 원본은 `assets-src/photos/`로 자동 백업되고, 축소·변환은 스크립트가 처리한다.
